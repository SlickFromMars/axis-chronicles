# Campaign Template

Copy this entire `_template` folder into a new folder under `campaigns/` and rename that folder to match the campaign ID (lowercase words separated by hyphens). Then update `campaign.json` and `manifest.json` to use the same ID/name. Register the new campaign in `campaigns/index.json`. Do **not** add `_template` itself to the campaign registry.

## Included files

- `campaign.json`: all currently supported campaign configuration fields, including tabs, theme colors, file paths, text labels, quest categories, party teams, character categories, and map settings.
- `manifest.json`: installable-app metadata. Keep its name, description, start URL, scope, colors, and icon paths aligned with the campaign.
- `data/characters.json`: sample player character and NPC, showing both `team` and `location` usage across entries.
- `data/quests.json`: sample main and side quests, including objectives, character/location references, and developments.
- `data/locations.json`: sample region, settlement, and landmark with map coordinates and a region reference. Coordinates are percentages from 0 to 100. The settlement demonstrates every optional detail field (see **Location fields** below).
- `data/sessions.json`: sample scheduled session. Replace or remove it before publishing.
- `data/music.json`: sample music page and playlist sections. Replace the placeholder playlist URLs.
- `assets/characters/portrait-manifest.json`: maps character IDs to portrait filenames. Add matching image files in this folder, or remove sample entries until portraits exist.

## Important

The sample entries are intentionally illustrative. Replace or delete them before publishing. Every `id` should be unique within its data file. References in quest `characters` and `locations`, and location `region`, must match real IDs. The `team` values should match an ID in `party.teams`. Add the map image at `assets/map/map.webp` and branding images at the paths listed in `campaign.json` if you want to use those features. Calendar `.ics` files are generated by the repository preparation script; don't hand-edit a generated calendar.

## Location fields

Each entry in `data/locations.json` needs only `id`, `name`, `type`, `x`, `y`, and `description`; `region` is recommended for anything that is not a region. Every field below is **optional** and adds a section to the location panel on the Map page only when it is present.

| Field | Format | Shows |
| --- | --- | --- |
| `region` | Region ID or region name | Parent region (clickable) and region filtering |
| `tagline` | text | Short italic line under the name |
| `status` | text, e.g. `"Visited"` | Gold badge |
| `tags` | list of text | Small badges |
| `image` | file name, or path relative to the campaign folder, or `https://` URL | Banner image. A bare file name is looked up in `assets/locations/`. |
| `imageAlt`, `imageCaption` | text | Alt text and caption for the image |
| `facts` | list of `{ "label", "value" }` (or an object of label: value) | Key facts table (population, ruler, climate, and so on) |
| `landmarks` | list of text, or `{ "name", "description" }`; a name that matches another location's name or ID becomes a link | Notable landmarks list |
| `sections` | list of `{ "title", "text" }`; `text` may be a list of paragraphs | Titled lore blocks (history, rumors, and so on) |
| `notes` | list of text | Bulleted notes |
| `connections` | list of location IDs, or `{ "location", "note" }` | Clickable list of connected places, with optional travel notes |
| `characters` | list of character IDs | Characters shown as present here |

Some things are filled in automatically, so there is nothing extra to write:

- A region lists the locations that name it as their `region`.
- Characters whose own `location` matches this location's name or ID are listed, along with any named in `characters`. Clicking one opens their profile.
- Current quests that list this location in `locations` are shown, and quests that are no longer active appear under Past Quests.
- The older style of ending a description with `Notable Landmarks: A, B, C` (after a blank line) is still understood and shown as a landmark list.

The search box on the Map page also searches tags, facts, landmarks, sections, and notes. Section headings can be renamed per campaign with `text.map` in `campaign.json` using `landmarksLabel`, `notesLabel`, `regionPlacesLabel`, `connectionsLabel`, `charactersLabel`, `questsLabel`, and `pastQuestsLabel`.
